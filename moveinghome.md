# Moving @home to a New NVMe Drive

## Summary

Migrated the Btrfs `@home` subvolume from the system drive (nvme0n1p6) to a new NVMe drive (nvme1n1p1), reformatting it from NTFS to Btrfs in the process.

**Date:** 2026-08-18  
**Source:** nvme0n1p6 (unencrypted Btrfs, ~23GB in @home)  
**Target:** nvme1n1p1 (NTFS → reformatted to unencrypted Btrfs, 931GB)

**Note:** Both source and target are unencrypted Btrfs partitions. No LUKS or encryption was used.

---

## Initial State

```
nvme0n1p6  btrfs  OMARCHY  →  / (subvol=@)
                           →  /home (subvol=@home)
                           →  /var/log (subvol=@log)
                           →  /var/cache/pacman/pkg (subvol=@pkg)

nvme1n1p1  ntfs   New Volume  →  /run/media/mihai/New Volume (empty, 931GB)
```

---

## Steps Performed

### 1. Unmount the NTFS partition

```bash
sudo umount /dev/nvme1n1p1
```

### 2. Reformat nvme1n1p1 as Btrfs

```bash
sudo mkfs.btrfs -f -L HOME /dev/nvme1n1p1
```

This wipes the NTFS partition and creates a fresh Btrfs filesystem with the label `HOME`.

### 3. Create @home subvolume on the new drive

```bash
sudo mkdir -p /mnt/new-home
sudo mount /dev/nvme1n1p1 /mnt/new-home
sudo btrfs subvolume create /mnt/new-home/@home
```

### 4. Copy all data from old /home to new @home

```bash
sudo rsync -aP /home/ /mnt/new-home/@home/
```

- `-a` = archive mode (preserves permissions, symlinks, etc.)
- `-P` = show progress and allow resume

**Verify copy completed:**

```bash
sudo du -sh /mnt/new-home/@home/   # Should match /home size
sudo du -sh /home/
```

### 5. Update /etc/fstab

Replace the old `@home` entry with the new UUID:

**Get the new UUID:**

```bash
sudo blkid /dev/nvme1n1p1
# Output: UUID="21b6eafb-bcaf-4234-8ccf-8f240e246f01"
```

**Edit fstab:**

```bash
sudo nano /etc/fstab
```

**Old entry (pointed to system drive):**

```
UUID=1fd04efc-a99a-4baf-9a7b-09e0e740715d  /home  btrfs  noatime,compress=zstd,subvol=@home  0 0
```

**New entry (points to NVMe):**

```
UUID=21b6eafb-bcaf-4234-8ccf-8f240e246f01  /home  btrfs  noatime,compress=zstd,subvol=@home  0 0
```

### 6. Unmount temporary mount and reboot

```bash
sudo umount /mnt/new-home
sudo reboot
```

After reboot, `/home` mounts from the new NVMe drive.

### 7. Delete old @home subvolume (post-reboot cleanup)

The old `@home` subvolume is no longer mounted but still exists on the system drive.

**Mount the Btrfs top-level to access it:**

```bash
sudo mkdir -p /mnt/btrfs-root
sudo mount -o subvolid=5 /dev/nvme0n1p6 /mnt/btrfs-root
```

**Verify old @home exists:**

```bash
ls /mnt/btrfs-root/
# Should show: @  @factory  @home  @log  @pkg
```

**Delete it:**

```bash
sudo btrfs subvolume delete /mnt/btrfs-root/@home
```

**Verify and cleanup:**

```bash
ls /mnt/btrfs-root/
# Should show: @  @factory  @log  @pkg (no @home)

sudo umount /mnt/btrfs-root
sudo rmdir /mnt/btrfs-root
```

## Final State

```
nvme0n1p6  btrfs  OMARCHY  →  / (subvol=@)
                           →  /var/log (subvol=@log)
                           →  /var/cache/pacman/pkg (subvol=@pkg)
                           (~24GB reclaimed from deleting @home)

nvme1n1p1  btrfs  HOME     →  /home (subvol=@home, 24GB data, 907GB free)
```

## After Reinstalling Omarchy

If you reinstall Omarchy, the NVMe drive with @home already has all your data. Just point the system to use it:

### 1. Install Omarchy normally

Fresh install creates a new @home on nvme0n1p6.

### 2. Mount the NVMe drive temporarily

```bash
sudo mkdir -p /mnt/new-home
sudo mount -o subvol=@home /dev/nvme1n1p1 /mnt/new-home
```

### 3. Update fstab

```bash
sudo nano /etc/fstab
```

Replace the `@home` line with:

```
UUID=21b6eafb-bcaf-4234-8ccf-8f240e246f01  /home  btrfs  noatime,compress=zstd,subvol=@home  0 0
```

### 4. Delete the fresh @home subvolume

Mount Btrfs top-level and delete the new @home:

```bash
sudo mount -o subvolid=5 /dev/nvme0n1p6 /mnt/btrfs-root
sudo btrfs subvolume delete /mnt/btrfs-root/@home
sudo umount /mnt/btrfs-root
```

### 5. Unmount and reboot

```bash
sudo umount /mnt/new-home
sudo reboot
```

After reboot, `/home` will mount from the NVMe with all your data intact.

---

## Notes

- **Both partitions are unencrypted Btrfs** - no LUKS or encryption involved
- **rsync was used instead of `cp`** to preserve permissions, ownership, and symlinks
- **Reboot was required** because `/home` was busy with running processes (Hyprland, qbittorrent, pipewire, etc.)
- **The old NTFS partition was completely wiped** - ensure no important data exists before formatting
- **The old @home subvolume was deleted** post-reboot to reclaim disk space on the system drive
